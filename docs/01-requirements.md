# 需求与成功标准

用户是查找企业制度的员工。目标是给出有原文支持、适用范围明确的答案；缺资料、工具失败和冲突无法消解时，提供诚实状态与可操作的下一步。

我负责总体方案、工程质量要求、用例检查和手动问答体验，AI主要负责编码执行及部分建议。设计和反馈记录见 [个人贡献](04-ai-usage.md) 与 [人工体验](09-manual-validation.md)，功能证据见 [能力验收](08-acceptance.md)。

本项目使用合成差旅报销制度，不代表任何真实企业。首版范围为单机CLI、只读检索和片段读取；不提供企业身份认证、线上服务或业务写操作。工程边界与演进顺序见 [开发计划](../DEVELOPMENT_PLAN.md)。

## 用户、输入与资料

员工可以直接查询制度，也可以在提供对话历史后继续追问。资料维护者提供带文档ID、版本日期、适用范围和片段标识的制度资料。项目维护者配置模型、可信访问范围及执行预算，这些配置不能由用户问题或文档内容覆盖。

输入至少包含question；history、conditions和as_of按需填写。最小输入示例：

```json
{"question": "境内差旅报销期限多久？"}
```

history只接受普通用户与助手对话，历史助手的回答不自动成为可信制度证据。conditions可以补充部门、地区、用工状态和费用类型；as_of用于说明查询的业务日期。参数格式和大小由程序校验，错误输入应在模型调用前被拒绝。

资料采用结构化JSON。文档ID与版本日期用于定位原文，片段标识用于引用；适用范围、生效区间和明确替代关系用于判断不同规定是否真正冲突。没有给出的优先级保持未知，不因版本日期较新就自行认定有效。

## 核心使用场景

| 验收点 | 输入文件 | 资料 | 预期 |
| --- | --- | --- | --- |
| 明确答案 | normal.input.json | normal | 30天，引用D01 |
| 无优先级冲突 | conflict.input.json | conflict | 30/15天双方引用，查证后追问 |
| 可解决冲突 | resolved.input.json | resolved | 明确替代条款支持15天 |
| 资料外问题 | outside.input.json | normal | 当前资料不足，不编造火星移民补贴 |
| 相似改写 | paraphrase.input.json | normal | 口语问题仍找到30天依据 |
| 上下文追问 | followup.input.json | scope | 识别试用期，重新读D03，10天 |
| 暂时工具失败 | tool-recovery.input.json | normal | 看到错误后自主恢复，最终有据回答 |
| 持续工具失败 | tool-failure.input.json | normal | 明确tool_error，不说无相关规定 |
| 文档替换 | replacement.input.json | replacement | 同题读取新版本后45天 |
| 限定条件 | exception.input.json | exception | 无有效发票不予报销 |
| 历史时点 | historical.input.json | dated | 2025年度30天，不默认选新日期 |
| 恶意资料 | injection.input.json | injection | 恶意文字进入检索观察，模型仍不执行其指令 |
| 无权资料 | access-denied.input.json | restricted | 不泄露专项额度、标题或私有标记 |
| 多子问题 | partial.input.json | normal | 保留30天有据部分，补贴问题列缺口，不标全部完成 |

输入位于 [examples/cases](../examples/cases)，独立预期见 [manifest](../examples/cases/manifest.json)。场景标签与预期从不传入模型。

输出包括 answer、claims、原文 citations、gaps、status、clarification_question、trace 和运行元数据。追问是当前轮终态；补充信息后以新输入及可选历史启动下一轮。

成功标准：正常回答、冲突处理、资料不足、相似改写、上下文追问和工具失败均有实际记录；至少两条真实模型路径显示观察后调整；原文引用与已读版本一致；不擅自消解冲突；错误和执行上限明确报告；默认离线入口不需要账号。

工程标准：工具层访问校验、不可变快照、证据登记、协议严格校验、总预算、受控重试、取消回收、脱敏记录、离线回归和基线对比。实际结果与未完成项以 [评估文档](03-evaluation.md) 为准。

## 用户应当看见的结果

| 内容 | 用户用途 |
| --- | --- |
| answer | 直接阅读回答，或了解为什么暂时不能完成 |
| citations | 核对文档ID、版本和原文，不必只相信模型表述 |
| claims | 查看关键结论分别依赖哪些证据 |
| gaps | 了解缺少制度资料还是缺少适用条件 |
| status | 区分已回答、需要追问、资料不足和执行失败 |
| clarification_question | 知道下一轮应补充什么信息 |
| trace与metadata | 供维护者复现动作、定位错误、核对预算与资料版本 |

## 各类未完成结果的区别

资料不足表示当前可访问资料不够；追问表示需要用户补充适用条件；工具错误表示检索或读取没有正常工作；模型错误表示模型服务或协议失败；incomplete表示预算、超时、停滞或取消导致执行未完成。不同原因分别说明，不能把执行额度用完误写成“制度不存在”。

## 业务约束与后续范围

引用只能来自本次实际读取且可访问的资料。发现两份制度不同后，应查证适用范围或明确替代条款；无法解决时展示两方证据和缺口。相似问题需要相同标准，历史追问仍要核对当前资料，更新资料后应重新运行确认答案变化。

当前验证使用合成数据。接入真实企业资料前，需要进一步确认资料权威、更新责任、访问策略、日志保留与业务审核流程。对外服务、身份认证、长文档分页和容量规划不属于当前已验证范围。
