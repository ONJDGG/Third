# 人工检查与问答体验

记录日期：2026-11-02。检查者：项目作者。

## 检查方式

在自动验证之外，我人工检查了测试用例，并以普通使用者的身份手动模拟问答，关注能否顺利运行、能否看懂回答与引用，以及需要补充信息时是否知道下一步怎么做。根据体验提出建议，再检查说明与操作步骤是否得到改善。

记录形态为作者人工复核摘要，范围包括用例检查与手动问答体验。逐条终端记录、精确耗时和人工通过率未单独收集；已有AI复核JSON与本记录分别维护。

## 个人检查与改进闭环

| 检查内容 | 人工关注点或反馈 | 已落实的改进 | 可核对位置 |
| --- | --- | --- | --- |
| 入门操作 | 多条命令放在同一段不便逐步操作，应拆开说明 | README和运行手册按单个命令分块，说明执行目录与预期结果 | README快速运行、docs/06-operations.md |
| 用户问答过程 | 从用户视角实际提问，检查答案、引用、状态和补充信息提示是否容易理解 | 增加状态字段解释、正常与冲突场景的结果说明 | README、docs/08-acceptance.md |
| 测试用例 | 人工检查用例及预期，区分正常回答、资料问题与运行故障 | 用场景表关联输入、实际输出和验证记录 | docs/01-requirements.md、docs/03-evaluation.md |
| 模型使用 | 明确离线体验和真实模型调用的不同，模型接入需要可替换 | 给出独立后端与相应运行步骤，保留真实调用记录 | src/providers/、docs/06-operations.md |
| 文档完整性 | 检查说明是否覆盖设计、决策、测试、故障和使用方式 | 用技术验收文档集中展示能力、证据和边界 | docs/02-solution.md、docs/08-acceptance.md |

人工体验中提出的具体改进以实际反馈和已落实内容为准。代码修复、自动执行日志与AI辅助核对各有独立记录，便于回看来源。

## 当前结论与后续检查

本轮人工检查补充了自动测试无法直接判断的使用体验，尤其是分步操作、结果解释和追问提示。它不等于线上用户调研，也不替代权限、安全或大规模业务准确性验证。

后续适合继续收集不同表达、不同适用条件和多轮追问的真实使用反馈，对每项反馈记录问题、修改与复验结果。当前已完成的代码验证、失败修复和限制见 [评估文档](03-evaluation.md)。
