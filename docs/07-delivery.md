## 确认版本

每个版本用完整的Git提交SHA标识。下载或复现时应使用同一版本的代码、资料与验证记录：

```text
git rev-parse HEAD
```

最终版本号以实际发布的提交为准。CI结果应与该提交对应，历史成功记录不替代当前版本检查。

## 复现顺序

1. 按README运行离线示例，理解回答、引用、缺口和状态。
2. 运行工程测试，检查格式、权限、版本、故障及执行边界。
3. 运行离线场景评估，保存自己的输出到新目录。
4. 配置自己的可用模型，运行相同场景验证真实决策。
5. 对照原文复核答案，记录人工使用反馈及待改进项。

Mock不需要密钥。真实模型需要使用者自己的模型服务或本机CLI登录，项目不分发任何账号认证材料。具体命令见 [运行手册](06-operations.md)。

## 打包与材料边界

在已提交且工作区干净时执行：

```text
python scripts/package_submission.py --output dist/enterprise-agent.zip
```

归档从Git中的规范化内容生成，附文件哈希与提交SHA，便于核对完整性；不包含.git、.local、虚拟环境、密钥或本机网络配置。固定归档时间戳用于稳定打包，实际投入记录另见评估文档。

仓库中的制度与问题均为合成测试材料。公开记录只保留业务验证需要的字段。企业身份平台、线上部署、容量验证、真实业务资料审批及自动长文档接入不属于当前已交付能力。
